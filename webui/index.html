Obsidian canvases are graphs. Each text node becomes a chunk that carries its own edges — preview first, then queue.

The edges you drew between nodes are the one place in the vault where you already wrote down how two ideas relate. This lane flattens them into each chunk at ingest time as a Connections footer plus aligned edge metadata, which is what the Graph RAG panel on the Query tab traverses. Scope with a real folder rather than a guessed substring; stamp a domain, because canvas filenames almost never carry a course keyword and unscoped chunks land as general / unknown; then Preview — it runs the real loader into a scratch file, indexes nothing, and reports what you would actually get.
Scanning the vault for canvases…

What the graph lane gives you

Why this is its own section rather than a file type.

Only text nodes become chunks. file, link and group nodes never get their own chunk — chunking a file node would duplicate a note the vault already indexes. They still appear as edge endpoints and as a node's enclosing group.
doc_ids are keyed on the canvas node id, not on the text. Two nodes saying the same thing don't collide, and editing a node's text upserts that chunk instead of orphaning it. Re-running this lane over the same canvases is safe.
Node depth is a real cost. Inlining a neighbour's text duplicates it into every chunk that links to it. Measured on this vault: depth 1 ≈ 1.26× the canvas index text, depth 2 ≈ 1.36×. Preview reports the exact share for your scope before you commit.

Appearance

Themes and description mode are browser-local (saved in this browser, not in config.yaml). The two shelves keep dark and light presets apart; click a chip to apply it. Custom presets carry ✎ rename and ✕ delete; built-ins don't. The header theme button cycles through everything on both shelves.
Paste --var: value; pairs, with or without a {…} wrapper — Export shows every variable the console uses. Omitted variables inherit from Ledger dark. Saved presets live on the shelves above with rename / delete.
Importing merges and never overwrites: a key that already exists with different content comes in as key-2 (then -3…), identical presets are skipped, and a file that fails validation changes nothing. Both the wrapped file and a bare {key: {label, mode, css}} map are accepted. The single-preset export and Save above work as before.

Vaults — switch document sets

Every vault ever opened stays listed. Switching snapshots the current vault's path/index settings, then restores the target's last-known ones — a brand-new vault gets its own empty index trio scaffolded. Nothing hot-applies: restart :8051 + :8052 after switching.

One vault at a time, each with its own everything: the console remembers each vault's own settings (vault root, chunks JSONL, Chroma dir, BM25 pickle, collection, inbox) and swaps the whole set atomically. Indexes are never shared between vaults — a new vault starts empty and fills through the normal ingest lanes. Forget only drops the registry entry; nothing on disk is touched.

Paths & models — persisted to config.yaml

Saved values are written into config.yaml in place (comments preserved). Nothing hot-applies — the save response tells you which services to restart. Point these at a different vault / index pair to run this console against another RAG.

Typical setups: another vault = change the vault root AND give it its own Chroma dir + BM25 pickle + chunks JSONL (each corpus needs its own index trio — mixing them corrupts nothing but retrieves nonsense). Embedding model: changing it makes every existing vector incompatible — you must re-embed the whole corpus (main.py index) before search works again; the cross-encoder and generation settings are safe to swap freely. Enum defaults (rerank / chunking) only set the config default; per-call overrides in Query/Ingest always win.

Experimental features — built and tested, not yet part of the default workflow

Off means the feature's controls are hidden, not merely disabled — an unproven panel sitting in the Query tab implies it is part of how you work. Turning one on writes config.yaml straight away and tells you what to restart.

These are features whose cost is known and whose benefit is not measured yet. They ship switched off on purpose: the honest place for a mode nobody has scored against the golden set is behind a flag, not in the default Query tab. Nothing here affects ordinary Ask / Search, and nothing here is removed from the API — the endpoints answer 503 with the reason while the flag is off, so an agent gets an explanation instead of a silent miss.

How this RAG works

A hybrid-retrieval RAG over your own documents. Several lanes search in parallel — dense (vectors) and sparse (keywords) always, others when enabled or triggered — and their ranked lists are fused into one candidate pool. A reranker reorders it, an optional relevance gate can discard weak chunks, an optional expansion step widens what is left to its parent section or neighbouring pages, and a cited answer is generated from those chunks. Retrieval and reranking run locally by default; the LLM writes the answer, and also drafts HyDE text, HyPE questions and citation checks when those are on. Hover, focus or click any stage to see what it does, which config.yaml keys control it, and whether it is on in the live config right now.

reading the live config…
Solid = always on; dashed = optional; blue dashed = optional and opened by the question itself; dotted red = experimental; dotted grey = the untouched original question. A filled dot on a stage means it is on in the live config.yaml, a hollow dot that it is off. Every retrieval lane lands in the same candidate pool, so adding a lane can only add candidates, never hide any. HyDE reshapes what retrieval searches for, but the reranker, the gate and the generator all work from your original question. The dot shows the config default; a preset or a per-call toggle can change a stage for one query, and the retrieval echo under each answer shows what really ran.
The ingest side has its own diagram — flip the toggle above.
Solid = always on; dashed = optional; blue = automatic. A filled dot on a stage means it is on (or selected) in the live config.yaml, a hollow dot that it is off. The loaders differ per format, but they share one JSONL contract: every chunk lands in data\*_chunks.jsonl with the same doc_id rule and metadata, and that is the corpus. The indexes are derived: lose either and it rebuilds from the JSONL files. index --append embeds only new doc_ids, so re-running anything is safe; a text edit mints new doc_ids, a metadata edit goes through retag with no re-embed. The chunking picker only changes how oversized sections split; sections that fit are identical either way. The query service keeps its indexes warm — restart it after any index change.

The Query knobs — what each one changes

Everything is per-call and leaves the warm defaults untouched. The retrieval echo under each answer shows what actually ran. General rule: tune retrieval on Search only (free, local, shows scores) and spend one Ask once the right chunks are surfacing.

KnobWhat it controlsEnable / raise ⟶ vs ⟵ disable / lower
presetA named bundle of the knobs below. code = wide + no HyDE + code-boosted; concept = tight + HyDE; synthesis = wide + HyDE + parent/neighbor context.Pick code for “my implementation of X”, concept for a definition, synthesis to connect topics. Blank = auto (code-intent queries self-apply code).
rerank_krerank_top_k — how many reranked chunks reach the LLM.Raise for richer, multi-source answers; lower for a tight, focused answer. Config default: ….
dense_kdense_top_k — vector/semantic candidate pool into fusion.Raise for paraphrase/conceptual questions (wider semantic net); the reranker still trims. Config default: ….
sparse_ksparse_top_k — BM25 keyword candidate pool into fusion.Raise for exact terms, code identifiers, names, error strings. Config default: ….
max tokensCaps the answer’s output length (Ask only).Small for a quick fact; large for a full synthesis. Config default: ….
HyDESearches with a hypothetical answer instead of the raw question — helps conceptual recall.ON for concepts/paraphrase. OFF for code / exact-term / “my script” queries (the prose hypothetical drags in lecture notes). The code preset turns it off for you.
HyPEAdds a lane matching your query against pre-generated hypothetical questions per chunk.ON when your wording differs from how the material is written. Safe to try — fails soft if the HyPE collection hasn’t been built. Config default: ….
OmnisearchFuses live-vault hits from Obsidian (notes not yet ingested).ON for “this week / today / just wrote”. Needs Obsidian open with the Omnisearch HTTP server; else zero live hits, no error.
rerankHow the fused candidates are reordered before the top-k cut. cross_encoder = in-process semantic scoring; http = the configured external /v1/rerank service; lexical = model-free query-term coverage; none = keep the fusion order; laya = the experimental fine-tuned scorer, refused unless its flag is on.Use http when a reranker runs on better host hardware, lexical for exact identifiers or zero model load, and none to inspect fusion itself. default follows retrieval.rerank_mode.
parents / neighborsE2 small-to-big, post-rerank: parents swaps a matched note chunk for its FULL enclosing section; neighbors appends a PDF hit’s adjacent pages as marked supplementary sources.ON when citations are on-topic but fragmentary (the synthesis preset carries both). OFF to keep sources tight. default = preset/config value.
